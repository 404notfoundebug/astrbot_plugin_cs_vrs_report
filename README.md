# 大肥鱼 CS2 赛果与预测

面向 AstrBot 的 CS2 职业赛事插件，支持比赛列表、选手数据、大肥鱼风格 AI 点评、历史交锋胜率和 VRS 世界排名，也可向指定群自动播报新赛果。

数据源以 **完美世界优先、HLTV 备用**。所有成员均可使用查询指令，无需 AstrBot 管理员身份。

## 功能

- **赛果分析**：总比分、单图比分、双方选手 Rating、K-D、K/D，以及简短的“大肥鱼”点评。
- **赛前参考**：查看未来赛程，根据双方近一年的整场交锋记录计算历史胜率，附样本数和交锋明细。
- **世界排名**：查看 VRS 全球前 15 战队、积分、数据来源及采集时间。
- **自动群播报**：按群聊 UMO 订阅新赛果，保存投递记录，缺失统计等待重试，发送结果不明时暂停重发。

比赛列表、赛程和自动播报仅包含**至少一队属于当前 VRS 全球前十**的比赛；排名展示前 15 不会扩大比赛筛选范围。

## 安装

1. 在 AstrBot WebUI 的插件管理中上传本插件 ZIP；发布到社区后，也可通过插件市场安装。
2. 确认插件成功加载。Python 依赖由 `requirements.txt` 声明：`beautifulsoup4>=4.12,<5`。
3. 在已接入机器人的会话中发送 `/cs ?` 查看帮助，然后发送 `/cs` 查询赛果。

也可以将插件目录放到 `data/plugins/astrbot_plugin_cs_vrs_report/` 后，在 WebUI 重载插件。

已验证环境为 **AstrBot v4.29.3、Linux、QQ/OneBot**。其他版本和平台尚未逐一验证；机器人须已具备收发消息能力，并能访问数据源。插件查询不需要完美世界账号、Steam Cookie 或登录令牌。

不使用 AI 点评时，无需配置大模型。开启 AI 点评时，使用 AstrBot 已配置的模型，可能产生对应模型费用。

## 指令

| 指令 | 功能 |
| --- | --- |
| `/cs`、`/cs list`、`/cs列表` | 查看近两天已结束的比赛，最多 20 场 |
| `/cs 2` | 查看赛果列表第 2 场的选手数据与分析 |
| `/cs预测`、`/cs pre` | 查看未来 7 天双方已确定的比赛，最多 20 场 |
| `/cs预测 2`、`/cs pre 2` | 查看未来列表第 2 场的历史交锋胜率 |
| `/cs vrs` | 查看 VRS 全球前 15 战队及积分 |
| `/cs ?`、`/cs ？` | 查看完整帮助和使用说明 |

### 使用示例

查看一场已结束比赛：

```text
/cs
/cs 2
```

查看一场未来比赛的交锋胜率：

```text
/cs pre
/cs pre 2
```

- 将示例中的 `2` 替换为对应列表内的序号，**不用加引号，也不填比赛 ID**。
- 赛果与未来赛程分别编号，不能混用。编号属于当前会话最近获取的对应列表，30 分钟有效，插件重载后需重新获取。
- 同群成员共用该群的列表；再次获取同类列表会更新该群的编号。
- 时间统一使用北京时间（UTC+8）。输入错误、编号越界或过期时，会返回原因和完整用法。
- 人工查询有插件实例范围的 10 秒限流；列表查询与详情查询分别计时，获取列表后可立即查看详情。

## 配置

在 AstrBot WebUI 的插件配置中修改并保存。

| 配置项 | 默认值 | 说明 |
| --- | --- | --- |
| `enabled` | `false` | 是否开启自动群播报；不影响手动查询 |
| `target_umos` | `[]` | 自动播报目标群的完整 UMO 列表，最多 20 个 |
| `source` | `auto` | `auto`：完美世界优先、HLTV 备用；也可选 `perfectworld` 或 `hltv` |
| `poll_seconds` | `300` | 自动检查间隔，单位秒，最低 120 秒 |
| `settle_minutes` | `5` | 比赛结束后等待统计完善的分钟数 |
| `lookback_hours` | `24` | 自动播报接受的新赛果结束时间回看范围；仍只扫描今天和昨天 |
| `stats_wait_hours` | `6` | 新赛果缺失选手统计时的最长等待小时数 |
| `max_reports_per_poll` | `3` | 每轮自动播报最多处理条数；程序限制为 1～10 |
| `ai_review` | `true` | 是否调用已配置模型生成点评；关闭时使用数据简评 |
| `provider_id` | 空 | 点评模型提供商 ID，留空沿用当前会话的模型 |
| `review_persona` | 空 | 自定义点评人格，留空使用默认“傲娇大肥鱼” |

### 开启自动群播报

1. 在接收播报的目标群发送 AstrBot 内置指令 `/sid`，获取该会话的完整 UMO。
2. 将它填入 `target_umos`，每项一个完整字符串。例如 `qq-snowluma:GroupMessage:123456789`。前缀取决于你的平台实例，**不要照抄示例，也不要只填群号**。
3. 开启 `enabled` 并保存配置。

只接受群聊 UMO。没有配置接收群时，不会主动抓取或投递自动播报；手动查询仍然可用。新增或重新启用的目标群首次成功检查只建立基线，**不补发已经结束的历史比赛**。

### 点评模型

点评只接收结构化比赛事实，比分和选手数据由程序生成，不让模型改写。默认要求 1～3 句简短评论，不编造战术、残局或实际观赛细节。输出最多 140 字符，同一份数据、模型与人格的点评缓存 7 天。

未找到可用模型、模型调用失败或关闭 `ai_review` 时，返回基于数据的固定简评。历史胜率由代码计算，不调用大模型。

## 数据口径

### VRS 与选手统计

排名来自数据源的 **VALVE/VRS 全球榜**，不是普通 HLTV 积分榜。它是实时估算数据，可能与 Valve 定期发布的正式邀请榜不同；输出会标明数据来源和采集时间。前 15 排名要求 15 支唯一队伍及完整积分，数据不足时会提示错误。

选手统计取源站明确的全场分组，不混入 T/CT 分项，也不对单图 Rating 简单取平均。Rating 使用原站数值；源站没有给出版本号时，不猜测为 Rating 2.0 或 3.0。

- **K-D**：击杀数与死亡数。
- **K/D**：击杀数除以死亡数；有击杀且死亡为 0 时显示 `∞`，0/0 显示 `—`。
- 完整选手统计尚未发布时，手动查询提示稍后重试；自动播报等待重试，不用虚构数值补齐。

### 历史交锋胜率

使用完美世界提供的近一年交锋记录，保留近 365 天有明确胜负的整场系列赛：

```text
A 队历史交锋胜率 = A 队获胜场数 ÷ 双方有效交锋总场数 × 100%
```

例如 A 队 2 胜、B 队 1 胜，则显示 A 队 `66.7%`、B 队 `33.3%`。按比赛 ID 去重，排除目标比赛、未来记录、平局和缺失比分，双方顺序反转时会翻转比分。百分比按全部有效样本计算，最多展示 10 场明细。

零样本时不默认填 50%；样本少于 5 场时提示参考性有限。预测时会重新确认目标比赛尚未开始、双方未发生变化。

**这是历史交锋频率，并非经过校准的未来获胜概率。** 它没有考虑阵容更换、地图池或近期状态，历史 100% 也不代表必胜。

## 数据来源与可用性

公开赛事数据来自 [完美电竞 CS 赛事数据中心](https://data.wanmei.com/) 和 [HLTV](https://www.hltv.org/)。本插件并非上述平台的官方产品。

- 赛果和选手统计支持完美世界优先、HLTV 备用；赛程、交锋胜率及前 15 排名目前仅支持完美世界。
- 使用 `hltv` 单一来源模式时，后面三项功能会提示不支持；建议使用默认 `auto` 或 `perfectworld`。
- 完美世界使用其公开网页客户端的访客请求协议，不需要用户私密凭据。网页和接口结构变化后，插件可能需要更新。
- 请求收到 401/403 时对该来源退避一小时，429 按限制退避，不绕过验证码或访问控制。
- 完美世界链路已经实际网络验证。验证环境中 HLTV 直接访问返回 403，HLTV 分支仅通过结构化样例测试，不能保证在其他网络环境可用。

## 常见问题

**发送指令没有回复？**

先确认机器人正常在线、插件已启用、当前会话允许使用本插件，以及 AstrBot 的指令前缀包含 `/`。本插件不要求管理员身份，但 AstrBot 全局白名单、会话开关或其他管理设置仍可能限制消息处理。

**为什么没有某场比赛？**

检查是否在查询时间范围内、是否至少一队属于当前 VRS 前十，以及数据源是否已经收录。未来列表只显示尚未开始且双方已确定的比赛，不显示 TBD 对阵。

**为什么提示刚检查过？**

所有成员共用插件实例的查询限流。等待 10 秒后重试；多人同时查询时也可能触发。

**为什么自动播报没有补发旧赛果？**

首次成功检查只建立基线，后续新出现且符合条件的赛果才会推送。还需确认 `enabled` 已开启、UMO 正确、统计完整且机器人有发言权限。

**自动发送结果不明怎么办？**

插件会暂停该条自动重发，避免重复消息。请维护者先检查群内实际消息及服务器记录，再人工处理；聊天指令不提供强制重发入口。网络投递无法保证严格的端到端只发送一次。

## 数据保存与开发验证

持久化数据保存在：

```text
data/plugin_data/astrbot_plugin_cs_vrs_report/state.sqlite3
```

其中包含订阅群 UMO、发送状态、播报内容及点评缓存。备份机器人时可一并备份；公开仓库、Issue 或截图中请勿携带这些运行数据、API Key、Cookie 或 SSH 密钥。

在插件目录安装开发测试依赖并运行：

```bash
python -m pip install -r requirements.txt pytest
python -m pytest tests -q
```

从插件目录的父目录运行只读数据检查：

```bash
python -m astrbot_plugin_cs_vrs_report.probe
```

探测程序只读取排名与赛果，不调用大模型、不发送 QQ 消息。已完成 23 项自动测试，以及 AstrBot 实际环境中的指令参数解析、路由和公开数据读取验证；真实自动群投递仍取决于平台适配器与目标群配置。

反馈问题时请提供 AstrBot 版本、插件版本、平台适配器、触发指令及脱敏错误日志。
